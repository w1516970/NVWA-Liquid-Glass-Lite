# NVWA 液态玻璃 · Lite 性能优化版

在原版 1.4.2 基础上的纯性能优化 fork。**主界面（顶栏 / 输入框 / 首页 / 弹窗）的玻璃效果一个参数都没动**，
所有优化都集中在长聊天时吃配置的细节上。安装方式与原版完全相同（扩展 → 安装扩展 → 选这个目录 / 仓库），
配套主题照常导入。与原版不要同时启用。

## 改了什么

### JS（index.js / glass2.js / orb.js / card-clarity.js）
| # | 优化点 | 原版行为 | Lite 行为 |
|---|---|---|---|
| 1 | 滚动时的顶栏自适应采样 | 每帧 8 个采样点 × 每岛，一次滚动触发上百次 `elementsFromPoint`（实测 288 次 / 1.5s） | 滚动中不采样，停手 150ms 后 3 个采样点补一次（实测 0 次） |
| 2 | 楼层指示条 | 每次滚动线性遍历所有消息的 `getBoundingClientRect` | 二分查找，几百楼也从几十次布局查询降到 log₂(n) |
| 3 | 鼠标高光跟随 | pointermove 每次都改每块玻璃的滤镜颜色矩阵 | 停稳 60ms 后更新，全局限 8fps；滚动中不更新 |
| 4 | 正在流式输出的那条消息 | 高度每帧变化 → 滤镜整条重算 | 降级为纯模糊，停更 320ms 自动恢复折射 |
| 5 | 贴图缓存 | 满了就全部清空重建（每张要采样 2 万+ 像素再 PNG 编码） | LRU，只淘汰最久没用的，热门尺寸常驻 |
| 6 | 滤镜区域 | 高出 200px，流式输出经常越界重设 | 400px 余量，越界才重设；SVG 属性只在变化时写入 |
| 7 | 预渲染范围 | 视口外 200px 内才画滤镜，滚回来要现算 | 1200px 提前画好；更远的卡片回收滤镜节点 |
| 8 | 思考点阵小球 | 每帧 96 次 arc + fill，页面隐藏仍运转 | 预渲染精灵图一次 drawImage，页面隐藏即停 |
| 9 | 卡片文字清晰度扫描 | 监听整个 body 的所有变化，正文打字也触发整页扫描 | 只响应 iframe / 浮层语义变化，空闲时段执行 |

### CSS（style.css 末尾「性能优化层」）
- 视口外消息卡片卸掉 backdrop-filter、阴影与双层 mask（`.ilg-offscreen`）
- 消息卡片的 `drop-shadow` 头像投影换成等价 `box-shadow`（不触发离屏滤镜）
- 消息卡片去掉表面光泽层（顶栏 / 输入框 / 弹窗保留）
- 消息卡片加 `contain: layout style`，一条消息变高不再牵动整页布局
- 旋转彩环只在「正在生成的最后一条」播放

### 新增设置
- **消息卡省电模式**（默认开）：卡片边缘不画色散彩边与高光。这两段是滤镜链里最贵的
  （色散 = 3 次位移 + 3 次色彩矩阵 + 2 次合成），实测关掉后合成开销降低约三分之一；
  卡片中间平坦区本来就没有这两段效果，肉眼只差边缘一圈细彩边。介意可关，关后与原版一致。

## 验证数据（120 条消息压力页，Chromium）
- 滚动 1.5s 内 `elementsFromPoint`：288 → **0**
- 常驻滤镜节点：722 → **576**（feDisplacementMap 69→43，feColorMatrix 115→77）
- 截图像素差异（0–255 制）：桌面 **0.02**，移动 0.77 —— 肉眼无差别
- 软件渲染下滤镜合成本身是最大瓶颈（真实 GPU 上比例不同）；若仍觉得卡，
  依次尝试：关「消息卡省电模式以外的 refractMes」→ 兼容模式选「仅模糊」。

## 与原版的关系
只改了 index.js / glass2.js / orb.js / card-clarity.js / style.css / manifest.json，
其余文件（字体、图标、壁纸、安装脚本）与原版一致，主题 JSON 不需要重新导入。
